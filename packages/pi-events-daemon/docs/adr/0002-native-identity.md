# Entity identity is the source system's native identifier, never minted by us

EntityRef keys reuse the external system's canonical identifiers verbatim: GitLab/GitHub page URLs, k8s api-server REST URLs, image references in skopeo transport notation (`docker://`/`containerd://`), local paths — under the `external/`/`project/`/`user/` key prefixes. Only ephemeral condition entities get daemon-minted keys (sha1 of check + schedule + cwd). Agents never generate or parse keys: the profile layer holds the URL parser/canonicalizer (with lazy numeric-id resolution), the extension derives project keys from cwd, the daemon mints condition keys. The trade-off we accepted: key generation is mechanical and profile-owned, and the daemon carries zero identity invention — versus a self-invented opaque-id scheme, which would force a mapping table, invite drift from the source system, and break human readability in `states`/`reckon` output.
