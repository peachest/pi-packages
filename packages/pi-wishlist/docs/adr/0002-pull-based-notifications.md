# ADR-0002: 拉取式通知模型

**状态**：已采纳  
**日期**：2026-06-23（从现有代码追溯）

## 背景

pi-wishlist 需要在 npm 发布新版本或 GitHub star 变化时通知用户。通知方式包括 session_start 时的 widget 面板。

## 决策

采用**拉取式（pull-based）模型**：在 session_start 时集中检查所有包，对比上次快照，记录差异为事件。不做 webhook 或事件订阅。

## 权衡

| 选项 | 优点 | 缺点 |
|---|---|---|
| **拉取式（本方案）** | 架构简单，不依赖外部 webhook 端点，无状态；去重写入端（同事件不重复记录） | 只在 session_start 时检查，非实时；随着包数量增加检查时间线性增长 |
| **npm webhook / GitHub webhook** | 即时推送，服务器端统一 | 需要公开接收端点、认证密钥管理、持久化存储；对 pi 扩展而言部署复杂度不可接受 |
| **GitHub 定期调度（GitHub Actions）** | 不依赖用户会话 | 需要外部 CI 配置，pi 扩展生命周期不可控 |

## 后果

- 检查结果按包缓存，session_start 时异步执行不阻塞启动
- 同一天不重复检查（`check-state.json` 记录日期）
- 事件上限 30 条，超限后裁剪保留最近 15 条，防止文件无限增长
- GitHub API 有速率限制，通过 200ms 间隔节流 + 连续失败 3 次后 24h 冷却保护
