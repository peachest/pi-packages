# ADR-0001: 本地 JSON 文件存储

**状态**：已采纳  
**日期**：2026-06-23（从现有代码追溯）

## 背景

愿望单需要持久化存储：包列表、版本快照、通知事件、用户备注和设置。pi 平台提供 `ctx.storage` 接口（基于扩展专属的 JSON 文件），但扩展也可以选择自行管理存储。

## 决策

在 `~/.pi/agent/data/wishlist/wishlist.json` 存储所有数据。写入使用 atomic write 模式（写临时文件 → rename）。

## 权衡

| 选项 | 优点 | 缺点 |
|---|---|---|
| **`ctx.storage`** | 统一生命周期（随扩展卸载清理），pi 管理文件路径 | 数据结构和 I/O 控制权移交；不方便做原子写入 |
| **自管理 JSON** | 读写完全控制，atomic write 保证完整性，可直接操作文件做调试/迁移 | 需要自己管理目录创建和错误处理 |

选择自管理 JSON 的主要原因是 atomic write 的需求——愿望单在任何时刻都不应该丢失数据。`ctx.storage` 的写入方式不确定。

## 后果

- 存储路径是固定的，迁移时有预期位置
- 数据结构定义在 `WishlistFile` 接口中，版本演进通过向前兼容的字段添加
- 测试通过 `setDataDir()` 注入临时目录
